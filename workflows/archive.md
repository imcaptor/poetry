# 作品归档协议

## 归档原则

用户明确确认定稿或暂存时，才为近体诗建立可检索的作品目录。skill 保存流程规则；作品目录保存具体诗作、版本变化、校验结果和上下文。不要把单首诗的过程资料写回 `SKILL.md`。

默认归档根目录：workspace 根目录下的 `jintishi/`。

## 目录命名

新作目录命名为：

```text
jintishi/YYYY-MM-DD-诗名/
```

规则：

- 日期使用当天本地日期。
- 诗名未知时先用主题短语；定题后可重命名。
- 诗名或主题中的空格用连字符，去掉不适合文件名的标点。

## 必存文件

每个作品目录至少保存：

- `README.md`：题目、体裁、创作缘起、最终推荐稿、当前状态。
- `session.md`：用户原始请求、关键追问、创作取向、重要取舍。
- `versions.md`：三版初稿、用户选择、每轮修改和修改原因。
- `checks.md`：格律模板、`tools/check-meter.mjs` 格律校验结果、逐句平仄、押韵、孤平、重字、挤韵、查重结果、外部复核或需人工确认项。

有材料时再增加：

- `notes.md`：典故、意象、用字、禁忌、后续可改方向。
- `final.md`：只放最终稿和极短题注，便于快速打开朗读或复制。

## 写入时机

1. 仅在用户明确确认定稿或暂存后建目录和 `session.md`，记录用户请求与初步题意。
2. 将已展示的三版初稿写入 `versions.md`；用户选择、改句或重校的版本按发生次序追加，不覆盖旧版本。
3. 更新 `checks.md` 和 `README.md`，写入当前稿和已有校验结论。
4. 定稿前运行 `tools/check-meter.mjs` 校验格律；如有硬伤，先提醒作者并修改，复校通过后把报告写入 `checks.md`。
5. 定稿前运行 `tools/check-similar.mjs` 对全诗每句查重，结果写入 `checks.md`。
6. 用户确认定稿时写 `final.md`；用户确认暂存时，在 `README.md` 标注“未定稿”。

完成标准：仅凭诗名或目录名检索，就能看到这首诗从请求、取法、版本到校验的来龙去脉。
