# 近体诗 Skill 验收清单

用 writing-great-skills 检查此 skill 时，至少确认下面四项。

## 1. Invocation

- `SKILL.md` 的 description 负责触发诗歌任务，不把近体诗全部细则塞进 description。
- 近体诗触发词能稳定指向 `forms/jintishi.md`。
- 需要搜韵式复核时，指向 `tools/souyun-checker.md`，且不声称内置私有搜韵数据。

## 2. Information Hierarchy

- 通用诗歌规则留在 `SKILL.md`。
- 近体诗范围、流程、格律报告留在 `forms/jintishi.md`。
- 搜韵边界、字段映射、外部复核流程留在 `tools/souyun-checker.md`。
- 平水韵映射、格律表、典故库、样例和反例后续分别进入对应窄文件，不回填到 `SKILL.md`。

## 3. Completion Criteria

- 裸请求最多追问 3 个问题；缺信息时用默认继续。
- 创作必须先定体裁、起式、韵部和模板，再填诗。
- 输出前必须完成本地自检；硬伤未修不能交最终稿。
- 孤平是硬伤；五言或七言平收句除韵脚外只剩一个平声字时，必须改到无孤平，不能用“一三五不论”放过。
- 模型判断孤平不稳或被用户指出风险时，必须用 `tools/check-guping.mjs` 按平仄串复核，并把结果写入格律报告。
- 律诗必须检查颔联、颈联对仗。
- 有多音、古今音或外部工具冲突时，标“需人工确认”。

## 4. Pruning

- 同一规则只放一个权威位置；不要在多个 README 重复维护。
- 删除不改变行为的解释性句子。
- 搜韵相关内容只保留合法接入边界与复核协议，不沉积抓取、缓存或私有数据复制说明。

## Smoke Prompts

- “帮我写一首七绝。” 应触发最多三问，随后按默认流程写三版并给完整格律报告。
- “按平水韵改这首五绝。” 应优先保留原意原字，先列硬伤，再给最小改动版。
- “用搜韵验一下这首七律。” 在没有用户提供结果或授权工具时，应做本地自检，并列出建议人工复核项。
- “万时一梦轻”若标为 `仄平仄仄平`，`tools/check-guping.mjs` 必须判为孤平且返回不通过。
